## 2025-02-28 - [CRITICAL] Fix SSRF in health check and web browsing
**Vulnerability:** The application allowed Server-Side Request Forgery (SSRF) through `checkUrl` (which had no validation) and `browseUrl` (which had incomplete validation missing cloud metadata IP `169.254.169.254` and various IPv6 private IPs like `::`, `fc00::`). This allowed an attacker to hit internal services or extract cloud instance metadata via the bot's health check feature.
**Learning:** Even when validation exists for one endpoint (`browseUrl`), other endpoints doing similar actions (`checkUrl`) might lack it. String-based URL validation is also tricky due to IPv6 formats (`[::]`) and multiple zero-representations (`0.0.0.0`).
**Prevention:** Apply a unified, comprehensive check before making any outbound HTTP requests on behalf of users. A better future fix would involve resolving the hostname to an IP via DNS before making the request to prevent DNS rebinding attacks.

## 2025-03-02 - [MEDIUM] Fix Reflected XSS in Telegram WebApp OAuth Callback
**Vulnerability:** The Google OAuth callback route (`webview/src/app/api/auth/google/callback/route.ts`) was returning user-controlled parameters (`error`) and state check errors as plain text responses instead of properly encoded and styled HTML pages. Not only did this present a minor reflected XSS vector (if the content type was misinterpreted by a browser), but returning raw text stranded the user inside the Telegram WebApp since it lacked the necessary JavaScript (`window.Telegram.WebApp.close()`) to dismiss the modal, severely degrading UX and security posture in a native environment.
**Learning:** In contexts like Telegram WebApps, returning raw text or unstyled errors is not just a bad user experience, it's a security flaw because users are trapped in an error state without a safe exit path. Furthermore, all dynamic content rendered in these callback templates must be explicitly HTML-escaped.
**Prevention:** Always use a standardized, HTML-escaped error rendering helper for OAuth callbacks. This helper must include the required Telegram WebApp SDK scripts and buttons to safely close the application (`window.Telegram.WebApp.close()`). Never return plain text `NextResponse` objects containing user input in WebApp routes.
